特徴量エンジニアリングのコードや SQL が変更された際に、データリーク観点でレビューします。

## チェック対象ファイル
- `src/ml/features/feature_query_raw.sql`
- `src/ml/features/*.py`
- `src/automation/data/jrdb_parser.py`

## レビュー観点

### 1. 発走後確定情報の混入
- 確定オッズ（発走後に確定）をモデル入力に使用していないか
- 確定馬体重（当日計測値）を過去走集計に混入していないか
- 着順・払戻金を特徴量として直接利用していないか

### 2. 同一レース内の情報漏洩
- 同一 race_id 内の他馬データを直接参照していないか
- 平均オッズ・頭数など、同レース集計値に当該馬が含まれていないか

### 3. 時系列境界条件
- 過去走集計で `race_date < 当該レース日付` の条件が正しく付いているか
- Window 関数や LAG で将来データが混入していないか
- `JOIN` で未来日付のマスタデータを参照していないか

### 4. Target Encoding / 統計集計
- 当該レース自身を除外した集計になっているか（条件別成績など）
- クロスバリデーション時に fold をまたいだ統計が混入していないか

## 出力形式
問題を発見した場合は以下の形式で報告してください:
```
[LEAK RISK] ファイル名:行番号
  問題: 〇〇が漏洩している
  修正案: △△に変更する
```
問題がない場合は「リーク検出なし ✓」と報告してください。
